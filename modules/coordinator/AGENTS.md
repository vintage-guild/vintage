# coordinator module

The autonomous raid coordinator (PLAN §6, #16): on a 5-minute Convex cron it creates upcoming
raids, posts signup messages, reminds non-responders, sends the officer digest, locks signups,
and posts the final roster and addon import string. Maturity: **core**.

## Shape

| Path | Holds |
|---|---|
| `src/contract.ts` | `CoordinatorConfig`, `CoordinatorAction`, `RaidNight`, command names |
| `src/domain/raid-night.ts` | Pure: option labels in the guild zone, `decideRaidNight` (what a closed poll means), the ops message when no raid is made |
| `src/domain/plan.ts` | Pure: `planTick(state, now)` → the actions due now, per raid and rule |
| `src/domain/card.ts` | Pure: the signup post, the private Roster reply, and the final roster as embeds with three role columns, our status icons, and class-colored squares |
| `src/domain/render.ts` | Pure: the plain messages (reminder, DM, digest, promotion, import string, failure) and the comp helper |
| `src/domain/emoji-ids.ts` | Generated by `scripts/discord-emojis.mjs`: the app's emoji name → id |
| `src/tick.ts` | `runTick(ports)`: settle raid nights → materialize → load → plan → claim → send → record |
| `src/store.ts` | `CoordinatorStore` (config, action log, raid nights), `CoordinatorPolls`, `TickSource`, `TickPorts`, `CoordinatorDeps` |
| `src/commands/` | `coordinator-status|pause|resume|run|config-set|log|repost`, `addon-import-get` (the import string the officer post carries, shared via `buildImportString`), and `raid-night-poll` in `raid-night.ts` |
| `src/testing.ts` | Memory store, fake Discord, fake raids, fake polls, state source |
| `convex/` | The `coordinator` component: `config`, `actions`, and `raidNights` tables |

## Rules

| Rule | When | Where |
|---|---|---|
| `post` | as soon as the raid exists | signup channel, with answer buttons |
| refresh | whenever the post's content changed (not logged) | edits the post |
| `promoted-<signup>-<time>` | when raids promotes someone from the queue | signup channel, mentions them once |
| `remind-<h>h` | each reminder offset, before lock; only the latest due one is sent | signup channel, pings non-responders only |
| `dm-<h>h` | the last reminder offset, if `dmReminders`; skips members who opted out | DM |
| `digest` | the last reminder offset | ops channel |
| `lock` | `lockHours` before start | runs `roster-lock` |
| `final-roster`, `import-string` | after lock | signup channel, ops channel |
| `raid-night` | a raid-night poll has closed (keyed by the poll id) | runs `raid-create`, or tells the ops channel why not |

- **Claim before send.** Every action is claimed in the component (one transaction) before it
  touches Discord, keyed by (guild, raid, rule, target). Re-running a tick, or two ticks at once,
  never sends anything twice. Keep new rules on this path.
- **Deterministic triggers; AI only for wording** (PLAN §6.2). Timings come from the raids
  schedule (`leadDays`, `reminderHours`, `lockHours`); channels, expected ranks, and DMs from
  `coordinator-config-set`.
- **Non-responders** are members whose rank is in `expectedRanks` and who have no signup.
- **Failures** are logged as `failed`, reported to the ops channel once, and retried next tick.
  A member who doesn't accept DMs (Discord 50007) is logged as skipped.
- Raids work goes through raids **commands** with the system caller (`schedule-materialize`,
  `roster-lock`, `raid-create`), never raids tables.
- **Raid-night polls (#64).** `raid-night-poll` (leader) makes the poll through the
  `CoordinatorPolls` port, which apps/api runs as `poll-create` for that leader, tagged
  `raid-night`. Each option's `value` is its start time. The raid's other details live in the
  `raidNights` table. The tick settles closed ones before `materialize`, so a new raid is posted
  in the same tick. The coordinator imports only polls' contract (the `Poll` type) and learns
  about a closed poll by reading it, not from the event bus, which has no subscribers yet.
- **A raid night's raid is created once.** `createForRaidNight` runs `raid-create` and marks the
  night `created` in one transaction, and the `raid-night` action is claimed per poll. A failed
  attempt leaves the night `pending` for the next tick to retry. A tie, a missed quorum, no votes,
  or a winning time already past creates nothing and goes to the ops channel.
- **Cards are embeds with three inline role columns** (Components V2 can't do columns), each
  headed by an outline role icon (`head_tank`, `head_healer`, `head_dps`). The description is
  the time, the lock and size as `-#` subtext, then the status counts spaced with em spaces. Each
  column shows up to `COLUMN_CAP` names then "+N more", so a 40-person card keeps its height; the
  **Roster** button (`roster:<eventId>`) shows everyone privately. `tests/card.test.ts` checks a
  full raid against Discord's embed limits. Icons are the app's own emoji (`emoji('status_late')`,
  `emoji('square_mage')`): our art in `assets/emoji` (`scripts/build-emoji-art.mjs`) plus Blizzard
  class and spec icons; add new ones to `scripts/discord-emojis.json` and re-run the upload script. A post deleted in Discord (error 10008) is reposted on the next tick;
  `coordinator-repost` replaces one on purpose and deletes the old message.
- **The signup post** shows a role counter line ("Tanks 4 · Healers 9 · DPS 25"), who's in by
  role with late people marked and everyone's reason (the signup `note`), the queue when the raid
  is full, tentative and bench with reasons, and comp gaps. The digest lists late, tentative, and
  bench reasons too. (Ideas from Raid-Helper: docs/research/raid-helper.md.)
- **Note triage (#132).** Before the digest goes out, one Decisions request labels every note on
  the raid (`domain/notes.ts`): its kind, and whether it asks an officer for something. Notes
  that do lead the digest under **Needs an officer**; offers to swap get their own line; every
  other note reads as before. `NOTE_THRESHOLDS` come from `tests/fixtures/signup-notes.json`
  (re-score with `pnpm --filter @vintage/coordinator exec tsx scripts/score-signup-notes.ts`).
  No `decisions` port, a paused agent, a refusal, or an error: the digest is exactly the old one.
- Button clicks (`signup:<eventId>:<status>` for accepted, late, tentative, bench, declined) go
  gateway → Convex `POST /gateway/interaction` → `apps/api/src/discord-signups.ts`: a character
  picker when needed, a reason form for Late and Tentative, private replies, and an immediate tick
  so the post refreshes in seconds.
